# 不撞场｜2026 筹款人交流会参会助手

> 把散落在公众号里的会议通知，整理成一份真正方便做选择的参会日程。
>
> **个人制作 · 非官方 · 非商业项目。** 本页面不是主办方的报名系统或最终议程，入场资格、会议安排请以主办方最新通知为准。

**[打开参会助手](https://rae-gu.github.io/fundraiser-2026-guide/)** · [查看网页源码](./index.html)

## 01｜为什么做这个？

准备参加 2026 公益慈善筹款人交流会时，我发现一件有点令人头大的事：

大会有不同主题的平行分会场，还有圆桌、工作坊、夜谈和市集；各场活动的详细介绍和报名通知，陆续发布在不同的公众号文章里。每篇文章单独看都很完整，但作为参会者，我还是得反复切换文章、自己拼出整张日程表。

我真正想知道的是：

- **有什么可选？** 各场到底在讨论什么，哪几场值得我花时间去听？
- **什么时候、在哪里？** 同一时段有哪些选择？想去的两场会不会撞车？
- **我能不能进去？** 有大会门票就够了吗？是否还要单独报名、申请审核或抢有限的名额？
- **最终怎么安排？** 能不能把想去、确定去、仍待报名的活动放在同一张个人日程里？

所以做了「不撞场」：不是再建一个新闻/推文合集，而是把分散的信息**按照参会者需要做的决定重新组织**，减少会前的信息整理成本。

这也是一次小型的参会数字体验实践：行业会议的内容很多，能不能让找到、比较、选择和参与的过程更轻松一点？

## 02｜需求与设计思路

这个工具主要解决五件事：

1. **集中查看**：把分会场及相关活动收进同一页，按日期、时段和议题呈现，并保留原文链接。
2. **比较与避开冲突**：同一时段的活动放在一起对比，自动提示已选择场次之间的时间重叠。
3. **区分兴趣与决定**：用「想去」和「计划参加」两种状态，不必一上来就做最终选择。
4. **管理报名门槛**：把活动的参与条件和自己的报名进度分开记录，避免“安排上了，却没有报名资格”。
5. **带走自己的安排**：形成个人参会清单，支持复制、分享和导出日历。

设计原则：**先帮参会者做判断；无法确认的信息，明确标注待核实，不猜测、不补造。**

## 03｜现在可以做什么？

| 你想做的事 | 页面入口 / 功能 |
| --- | --- |
| 在同一时段比较几个议题 | **按时段选场**：查看议题、时间、内容与报名提示，标记「想去」或「计划参加」 |
| 看清哪场与哪场冲突 | **时间总览**：查看排期及时间重叠；未确认时间的活动不会被当成无冲突 |
| 核对能否入场 | **报名门槛**：区分持大会资格可参与、另行预约、申请/审核、已截止/满额及待核实 |
| 记录自己报名到哪一步 | 在场次详情中设置「尚未报名」「已提交/待确认」「已获得确认」等个人状态 |
| 只看自己的行程 | **我的参会安排**：集中查看「计划参加」与「想去」，检查冲突及待处理的报名条件 |
| 把日程带走或发给同行者 | **复制清单 / 分享我的安排 / 导出日历 .ics** |
| 找到每条信息的出处 | **原文资料 / 关于**：查看公众号文章、来源链接、已核对摘要和未核实事项 |
| 新公告来了，补充场次 | **补充一场会议 / 编辑场次**：可填写主题、时间、会场、看点、预约入口等信息 |

## 04｜怎么使用？（建议按这个顺序）

1. **先选感兴趣的。** 打开[参会助手](https://rae-gu.github.io/fundraiser-2026-guide/)，进入「按时段选场」，在各个时间段中比较议题。暂时拿不准的标记「想去」，决定优先参加的标记「计划参加」。
2. **再检查撞场。** 进入「时间总览」，或者直接在「我的参会安排」查看所选场次是否重叠。如果想去的活动同一时间举行，就需要做取舍。
3. **逐场核对入场条件。** 进入「报名门槛」，查看是否另行预约、需要审核、有限额或尚待确认。通过原文或主办方渠道完成真实报名，再手动更新个人报名状态。**点「计划参加」不会替你报名。**
4. **生成个人日程。** 在「我的参会安排」中复制清单，或点击「分享我的安排」生成包含已选场次的链接，发给同行者讨论。已确认且具备完整起止时间的场次，还可以导出 `.ics` 日历文件。
5. **及时处理新消息。** 如果公众号又发布了调整，可通过「原文资料」查阅，或使用「补充一场会议 / 编辑」在本机更新内容。

不需要注册，也不需要安装 App；手机、电脑浏览器均可使用。

## 05｜数据从哪里来？目前整理到什么程度？

当前内容基于大会公开信息、相关公众号文章和参会者收集的线索整理，**更新基线为 2026 年 10 月 20 日**。

- 已录入 2026 年 10 月 23—24 日（上海）的 **8 场平行分会场**及其发布的时段。
- 另收录筹款人夜谈、AI 实操工作坊、两段圆桌咨询与同行者市集等相关环节。圆桌按时段归组显示，不等于只有两张桌。
- 已整理用户提供的 **16 篇微信公众号文章**，在「原文资料」中保留链接、核对摘要及所对应的活动。
- 对于夜谈单独报名、部分活动申请/遴选、工作坊限额等不同参与规则，尽量分开呈现，而不是统一写成“凭票参加”。

**还不完整的地方：** 部分文章内图片、二维码、具体会场房间、主论坛完整日程，以及报名截止时间、剩余名额和最终审核结果，尚未逐项核实。公众号推文与会务信息也可能更新，因此页面不保证实时性或完整性。

## 06｜使用时需要知道的限制

- **不是官方报名入口。** 「计划参加」只是自己的日程意向，「已获得确认」也是个人记录，并非主办方对报名结果的认证。
- **个人数据保存在当前浏览器。** 收藏、报名进度、补录场次与公众号笔记使用浏览器本地存储（`localStorage`）；换手机、换浏览器或清除网站数据，可能无法看到原先的记录。
- **本机补录 ≠ 网站公开更新。** 你在网页中编辑的内容只影响当前设备；如果要让所有访问者看到更新，需要修改 GitHub 仓库的 `index.html` 并重新发布。
- **分享前检查内容。** 「分享我的安排」会把所选场次的部分信息（也包括你自己补录的场次内容）写入分享链接，请勿把私人或敏感信息填入准备分享的场次字段。
- **无法判断的不算“没有冲突”。** 只有日期与起止时间完整的场次才能进入自动撞场判断。最终排期仍应与现场/主办方通知比对。

## 07｜项目运行与维护

这是一个轻量级静态网页，主要使用原生 HTML、CSS、JavaScript，无需数据库或后端服务。

```text
fundraiser-2026-guide/
├── index.html   # 页面、交互与内置会议信息
└── README.md    # 你正在阅读的项目说明
```

**本地运行**：下载仓库后直接用浏览器打开 `index.html`。

**在线部署**：由 GitHub Pages 托管，仓库 `main` 分支的 `/(root)` 目录发布。若[在线地址](https://rae-gu.github.io/fundraiser-2026-guide/)暂时打不开，请检查仓库 **Settings → Pages** 的发布状态。

**维护公开议程**：核对新公告、保留可追溯来源，在仓库中更新 `index.html` 内的场次或原文数据，再提交到 `main`。不要把个人报名状态等私有浏览器数据提交到公开仓库。

如果你发现信息有误、遗漏或发生变更，欢迎提供**对应的官方通知或公众号原文链接**，帮助修正内容。
